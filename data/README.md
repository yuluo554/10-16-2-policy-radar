## 二、数据源可获取性记录（供实现者）

1. **取数路径**：条目在 **`searchVO.listVO`**；响应顶层 `data` 字段实测为 `null`（不得按 `data` 取）。
2. **统一 schema**：两个频道返回字段一致，统一为 `title / pcode / pubtimeStr / puborg / url / summary / index / id`（另加我方可注入的 `source` 频道标识）。
3. **去重主键**：**`id`**（两频道实测非空）；`index` 只作副键（**部委频道实测 30/30 为空**）；`pcode` 非空时并入重复判定。
4. **增量策略**：因日期过滤失效，增量 = 本次抓取结果与本地快照 diff。
5. **限频礼仪**：逐页抓取加延时；只抓元数据，不做全文批量下载。
6. **失效预案**：API 字段或 `totalCount` 明显变化时，先更新本台账再动代码（未挂原文核对不得落库）。
7. **抓取产物（M2）不属于 `data/`**：`fetch` 写的是**运行时产物**（默认 `out/fetched.json`，
   `/out/` 已在 `.gitignore` 锚定），条目顺序 = API 返回序（K22）。`data/` 下只放
   **冻结资产**（样本 / 快照对 / 真值 / 规则表），不放运行时结果。

## 三、合成数据纪律（真值基准）

- **真值用预置快照对 + 程序化标注**：快照 A（旧）+ 快照 B（新），B 中相对 A 的新条目即"应判为新增"真值；A∩B 条目即"应判为重复"真值。标注脚本生成，人工只抽查。
- **真值库只存"输入与期望"**：**禁 `observed_*` 一类字段**（冻结"观测"会让基准退化成"比对两份预先算好的答案"，引擎全坏也全绿）；观测由基准运行时实算。
- **期望值必须可由输入独立复算**：生成器内含**独立朴素 oracle**（按 `id`/`pcode` 双键做集合差），落库前跑生成守卫（期望值与 oracle 重算逐条一致才许写盘）。
- **文号解析真值**：对预置条目的 `pcode` 逐条标注期望解析结构（机关代字/年份/序号 + 三态 `parsed/partial/unparsed`），解析失败样本显式标注"未解析"，不得编造。
- **样例文号用真实格式**：快照样本中的文号一律采用**实采出现的形态**（见第五节），并标注为"快照样本"；不得虚构不存在的发文机关代字格式或编造数值/日期。
- **反向样例必须有**：如 `国令第847号`（不该解析出年份）、空 `pcode`（不该解析出代字）——只测"该命中"的样例，适用域写错永远不红。
- **确定性生成**：自研 splitmix64（禁 stdlib `random`、禁 set 迭代序、禁系统时钟）；落盘产物无时间戳；配"再生成位级一致"两层守门（冻结产物形态 + 重跑逐字节）。
- **不写漂移硬数字**：`totalCount` 值、条数等会随时间漂移的数字只出现在本台账的"基准日实测"语境下，不得硬编码进代码或测试断言。

## 四、数值口径纪律

- 一切数值（`totalCount`、命中数、新增数）必须注明口径与基准日；
- 代码不得内嵌实测当天得到的 `totalCount`/条数作为断言；
- 日报中呈现的数字必须可由快照对 + 订阅配置复现。
