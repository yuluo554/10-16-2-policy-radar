## 二、数据源可获取性记录（供实现者）

1. 统一 schema：两个频道返回字段一致，统一为 `title / pcode / pubtimeStr / puborg / url / summary`（另保留 `index` 作为去重主键之一）。
2. 增量策略：因日期过滤失效，增量=本次抓取结果与本地快照 diff；重复判定可用 `index` 与 `pcode` 双键。
3. 限频礼仪：逐页抓取加延时；只抓元数据，不做全文批量下载。
4. 失效预案：API 字段或 total 明显变化时，先更新本台账再动代码（未挂原文核对不得落库）。

## 三、合成数据纪律（真值基准）

- **真值用预置快照对 + 程序化标注**：快照 A（旧）+ 快照 B（新），B 中相对 A 的新条目即"应判为新增"真值；A∩B 条目即"应判为重复"真值。标注脚本生成，人工只抽查。
- **文号解析真值**：对预置条目的 `pcode` 逐条标注期望解析结构（机关代字/年份/序号），解析失败样本显式标注"未解析"，不得编造。
- **样例文号用真实格式**：快照样本中的文号一律采用真实出现的格式（如"国办发〔2026〕28号"六角括号、年份四位、序号纯数字），并标注为"快照样本"；不得虚构不存在的发文机关代字格式或编造数值/日期。
- **不写漂移硬数字**：total 值、条数等会随时间漂移的数字只出现在本台账的"基准日实测"语境下，不得硬编码进代码或测试断言。

## 四、数值口径纪律

- 一切数值（total、命中数、新增数）必须注明口径与基准日；
- 代码不得内嵌实测当天得到的 total/条数作为断言；
- 日报中呈现的数字必须可由快照对+订阅配置复现。
