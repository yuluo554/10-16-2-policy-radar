## 二、冻结与验证纪律

- **样本是原始响应字节**（抓取器不重新 `json.dumps`）：样本的价值在于"那一刻服务器真返回了什么"。
  重新序列化会把"字节冻结纪律"偷换成"我们的序列化器输出了什么"。
- **`.gitattributes` 标 `-text`**（防克隆时 EOL 归一化改写字节 → sha256 失配）。
- **验证手段**（`git status` 看不出来）：克隆/检出后跑
  `py -3.8 -X utf8 tools/capture_samples.py --out-dir data/samples --check`
  —— 逐份重算 sha256 与登记值比对，**不打真站点**。
- **重新抓取会改变 sha256**（服务器返回含 `startTime` 等每请求不同的字段）：重抓必须
  连同 `manifest.json` 一起更新提交，并在本表登记新的抓取日期与 sha256。**这是正常更新，
  不是缺陷**；但"冻结"的含义是"提交后的字节不得被改动"，不是"永远不许重抓"。

## 三、边界与口径

- **只存元数据**：样本是 API 返回的元数据响应，**不含政策正文**（边界 2：不做全文下载归档）。
- **不写漂移硬数字**：样本里的 `totalCount`（`gwy=6222` / `bm=12803`）是**冻结的历史快照**
  （记录那一刻的返回值），允许存在于样本与登记表中；但**代码与测试断言不得内嵌该数**
  （M0 实测：`bm` 已由 12801 漂到 12803）。
- **取数路径**：条目在 `searchVO.listVO`，响应顶层 `data` 实测为 `null`（决策 D13）。
  `tools/capture_samples.py::validate_payload()` 对这两点做**结构性断言**，
  结构漂移即报错而非静默接受。
- **抓取礼仪**：逐请求延时（默认 3s）、单请求超时 20s、失败重试 2 次；只发只读 GET。

## 四、M1 复测新增的实采形态（补充 `data/README.md` 五之补充）

本轮抓取（2026-10-17，两频道各 30 条）除确认 M0 六形态外，又实采到三类**新形态**，
已纳入 `data/truth/pcode-truth.json` 的真值覆盖（含反向样例）：

| 新形态 | 实例 | 要点 |
|---|---|---|
| **全角 `﹝﹞` 括号变体** | `工信部联规﹝2026﹞210号` | 与 `〔〕` 不同码位（`U+FE5D/U+FE5E`），**不得按 `〔〕` 硬匹配** |
| **序号与"号"之间有空格** | `农农发〔2026〕9 号` | 序号后含空格，解析须容忍空白 |
| **机关名变体** | `住房和城乡建设部`（vs `住房城乡建设部`） | 别名表须同时登记两写法 → 同一规范名 |

**诚实口径**：复测范围仍是两频道各前 30 条（`p=1,n=30`），**不是全量普查**；
未覆盖的形态在后续里程碑增量补录（补录是追加事实，不改写既有措辞）。
