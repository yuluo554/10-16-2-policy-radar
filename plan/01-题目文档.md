# 10-16-2-policy-radar：政策文件雷达（国务院+部委）

- 产出仓库：`10-16-2-policy-radar`
- 版本：v1（2026-10-15 定稿）
- 形态：纯本地 Python CLI + 本地中文日报（本地定时跑，无服务器、无 GPU），发布 GitHub 公开仓库，署名 yuluo554

## 定位宣言

本地定时抓取中国政府网政策文件库，把"今日新发政策 + 发文字号 + 发布部门 + 摘要"变成一份可订阅关键词的中文日报——快照 diff 检测新增，不是每次全量翻页。企业法务 / 合规 / 政策研究 / 申报人员要盯发文，分散逐条翻页极易漏。

---

## 一、介绍

政策文件是企业法务、合规、政策研究、申报岗位的日常盯守对象。国务院政策库与部委政策库的发文分散在列表页里，人工逐条翻页极易漏看，等看到时往往已错过申报窗口或合规过渡期。

本题要求做一个**本地定时运行**的政策文件雷达：

- 数据源是中国政府网的**搜索 API**（国务院政策库 `zhengcelibrary_gwy` + 部委政策库 `zhengcelibrary_bm`，均为公开 JSON 接口，已实测可用，基准日 2026-10-15）；
- 通过**上次快照 diff**检测"今日新发"，不做全量翻页、不重复推送旧文；
- 发文字号（如"国办发〔2026〕28 号"）是 API 返回的**结构化字段**（`pcode`），天然可确定性解析，不需要大模型；
- 产出一份可订阅关键词的**中文 Markdown/HTML 日报**，命中订阅关键词的政策条目高亮呈现。

硬性纪律贯穿全题：**一切数据以 API 实测返回为准，未核对原文/字段不得落库、不得在日报中生效**；本地快照只存元数据与链接，不做全文归档；纯本地、无遥测。

## 二、任务要求（首期模块）

### 模块 1：国务院+部委双源抓取（统一 schema）

- 输入：中国政府网搜索 API 两个频道
  - 国务院：`https://sousuo.www.gov.cn/search-gov/data?t=zhengcelibrary_gwy&q=&p=1&n=5&sort=pubtime&sortType=1`
  - 部委：同 URL 换 `t=zhengcelibrary_bm`
- 输出：统一 schema 的元数据条目列表，字段至少含 `title / pcode / pubtimeStr / puborg / url / summary`（与 API 实测字段一一对应）。
- 确定性纪律：抓取目标 URL 以 API 返回的 `url` 字段为准（gov.cn 旧路径大面积 404，直连 `www.gov.cn/zhengce/zuixin/home.htm` 实测 404，必须走搜索 API）；遵守平台限频，逐页抓取间加延时。

### 模块 2：快照存储 + 新增检测

- 输入：本次抓取的条目列表 + 上次本地快照。
- 输出：更新后的快照文件 + 新增条目清单；重复出现（同 `index` 或同 `pcode`）的条目判为旧文，不再进日报。
- 确定性纪律：变更检测一律走"上次快照 diff"。实测 API 的 `mintime/maxtime`（`timetype=timedef`）日期过滤未生效（仍返回全量），**不得依赖日期参数做增量**，以 diff 为准。diff 判定必须可复现（同一对快照输入必须得到同一份新增清单）。

### 模块 3：发文字号与部门解析

- 输入：条目的 `pcode`（如"国办发〔2026〕28 号"）与 `puborg`。
- 输出：文号解析结构（机关代字 / 年份 / 序号），发布部门归一化结果。
- 确定性纪律：规则化解析，不做语义猜测；解析失败的字段显式标记"未解析"，不得编造文号、日期、部门名。

### 模块 4：关键词订阅 + 命中日报

- 输入：用户配置的多关键词与排除词；模块 2 的新增条目。
- 输出：命中清单（哪条政策命中了哪个订阅词）。
- 确定性纪律：命中判定基于标题与摘要的确定性匹配（含/不含、命中位置可回溯），不做相关性打分；同一关键词多次配置不产生重复命中。

### 模块 5：中文日报生成 + 真值基准

- 输入：新增条目 + 命中清单 + 解析结果。
- 输出：本地中文 Markdown/HTML 日报（按发布时间倒序，含标题、文号、发布部门、发布日期、摘要、原文链接、命中关键词标注）；配套真值基准——预置快照对 + 植入真值标注（哪些条目应判为新增、哪些文号应解析成什么结构）。
- 确定性纪律：**未挂原文核对（与 API 返回字段一致）不得落库/不得在日报生效**；日报可由基准数据完全复现。

### 扩展项（不计入首期验收）

- 地方政策库接入；部委站点直抓；webhook 推送（如邮件/IM）；本地定时调度（crontab/任务计划示例）。

## 六、边界与非目标

- **不做政策解读/咨询**：只做"新发变更提醒"，不输出任何解读观点，避免误导。
- **不做全文下载归档**：首期只存元数据 + 原文链接，快照不落全文。
- **不承诺覆盖所有发文渠道**：首期只接国务院政策库 + 部委政策库两个频道，不覆盖地方库与部委站点直抓（列为扩展项）。
- **隐私红线**：纯本地运行，无任何遥测、无账号、无上传。
- **平台礼仪**：遵守 gov.cn 限频，抓取加延时，不做高并发压测。
- **品牌隔离**：本仓库独立成题，文档与代码中不得出现任何其他姊妹项目名称。
- **首期范围限定**：以上四个"不做/不承诺"即首期边界，超出部分一律列为扩展项，不计入验收。
