## 一、data/ 目录结构（四类资产）

```
data/
├── README.md                数据依据台账（三态记录 + API 实测 + 合成纪律）
├── config/                  规则数据（生成器产物或人工冻结）
│   ├── org-aliases.json     部门别名表（单一来源，K7）
│   ├── subscribe.json       订阅配置样例（含/不含/重复词）
│   └── normalize.json       全半角归一表（K8 单一来源）
├── snapshots/               预置快照对（字节冻结 fixtures，禁手改）
│   ├── pair-A.json          旧快照
│   ├── pair-B.json          新快照
│   └── manifest.json        快照元信息 + 逐份 sha256
├── truth/                   真值台账（**只存输入与期望**，K11）
│   ├── diff-truth.json      新增判定真值（应判新增 / 应判重复）
│   ├── pcode-truth.json     文号解析真值（期望解析结构 / 期望"未解析"）
│   ├── subscribe-truth.json 订阅命中真值
│   └── README.md            真值语义说明（一次定清）
└── samples/                 真实 API 响应样本（离线回归用，冻结）
    ├── gwy-p1-n5.json       国务院频道真实响应
    ├── bm-p1-n5.json        部委频道真实响应
    └── README.md            抓取日期 + URL + sha256
```

## 二、数据来源与许可（每份登记）

| 资产 | 来源 | 许可/性质 | 备注 |
|---|---|---|---|
| `samples/*.json` | 中国政府网搜索 API（`sousuo.www.gov.cn`）实测响应 | 公开政府信息，元数据 | 抓取日期 2026-10-17；URL 与 sha256 入 `samples/README.md`；**只存元数据不含正文** |
| `snapshots/pair-*.json` | **程序化合成**（生成器产出） | 自制 | 用**真实文号格式**（实采形态），标注为"快照样本"；**不编造不存在的机关代字** |

| `config/org-aliases.json` | 从实测 `puborg` 取值归纳 + 人工登记 | 自制 | 只登记**实测出现过的**部门名与其规范名；未出现的不编造 |

**"不写漂移硬数字"纪律**：`totalCount`（6222/12803）这类会随时间漂移的数字**只出现在 `data/README.md` 的"基准日实测"语境**，不得硬编码进代码或测试断言。抓取样本文件里的数字是**冻结的历史快照**，允许存在（它记录的就是那一刻的返回值）。

## 三、合成数据纪律（真值基准，M1 核心）

### 3.1 快照对生成器（`tools/gen_snapshot_pairs.py`，M1 产出）

- **确定性生成**：自研 splitmix64 RNG（禁 stdlib `random`）；固定 seed；**全程不读时钟**；落盘产物无时间戳。
- **两层位级守门**（skill 头号假门来源）：
  ① **冻结产物自身形态正确**（如 B 相对 A 的新增数 == manifest 声明数）；
  ② **重跑生成器到临时目录 → 与冻结产物逐字节比对**（`--check` 通路）。
  判别 = "这个守门测的是产物还是生成器？"——必须真跑一遍生成器。
- **期望值独立可复算**（skill 核心纪律）：真值里的"应判新增"**不由主实现算出**——生成器里**独立重写一遍朴素 oracle**（按 id/pcode 双键做集合差），落库前跑**生成守卫**（期望值与 oracle 重算逐条一致才许写盘）。
  判别 = "把主实现的 diff 逻辑注释掉，真值还能算出来吗？"——不能即同源，基准会跟着实现一起错。
- **快照对必须覆盖三类形态**（题面评分"真值基准覆盖应判新增/重复两类样本"）：
  | 形态 | 样本 | 说明 |
  |---|---|---|
  | 应判新增 | B 中 id 不在 A | 标准新增 |
  | 应判重复 | id 相同 | 双键之一命中 |
  | **应判重复（pcode 键）** | id 不同但 pcode 相同 | **专测副键**：只按 id 判会漏掉这条 |
  | **边界：pcode 空 + id 新** | 部委条目 | 实测形态：`index` 空、`pcode` 可能空 → 只能按 id 判 |
  | **边界：pcode 空 + id 同** | 部委条目 | 空 pcode 不得导致"误判新增" |
- **人工只抽查**：真值由脚本生成，人工复核抽样并在 `truth/README.md` 记录抽了哪几条。

### 3.2 文号解析真值（`pcode-truth.json`）

- 逐条标注期望：`{pcode, expect: {agency_code, year, serial, status}}`，`status ∈ parsed/partial/unparsed`。
- **失败样本显式标"未解析"**：`国令第847号` → `year: 未解析`；空 pcode → 三字段全 `未解析`。
- **反向样例**（skill 适用域条）：必须有"不该解析出某字段"的样本，否则"解析器把什么都填上"永远不红。

### 3.3 订阅命中真值（`subscribe-truth.json`）

- 逐条标注：`{item_id, expect: [{keyword, field, offset}]}`。
- 含"命中 0 次""只命中 exclude""同词重复配置"三类边界样本。

### 3.4 真值语义一次定清（写进 `truth/README.md` + 生成器模块注释）

- **主期望 `expect`** + **隐含结论 `also_expect`**（如"B 新增"隐含"A 侧无此条"）。
- **对账语义单一实现源**（`benchmark/cases.py` 的 `compare_*` 函数）供测试与基准共用——否则"基准说达标、测试说不过"。
- **禁 `observed` 字段**（K11）：真值库出现 `observed_*` 即红——冻结"观测"会让基准退化成"比对两份预先算好的答案"。
- **不许改真值凑引擎**；但分两情形（skill）：① 谓词自身不自洽 → 只改谓词；② 口径本身定错 → 引擎与真值**同源修正**（两边一起改 + 重生成 + `--check` 仍过）。

## 四、数值口径纪律

- 一切数值（total、命中数、新增数）注明**口径与基准日**；
- 代码**不得内嵌**实测当天得到的 total/条数作断言；
- 日报中呈现的数字必须可由"快照对 + 订阅配置"**完全复现**（题面硬要求）；
- 生成器落盘用 `open(..., newline="\n")`（3.8 无 `write_text(newline=)`）+ `ensure_ascii=False`。

## 五、验收门槛随数据下发（skill 纪律）

基准的验收门槛（如"diff 判定准确率 ≥ 阈值""pcode 解析覆盖率 ≥ 阈值"）落 `data/truth/manifest.json`，**基准层只读、缺失即报配置错误 exit 2**，**不得回落代码里的默认值**——门槛内联进代码就是"抄进代码的第二份真相"。
