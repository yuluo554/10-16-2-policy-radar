# 04：模块详设

- 上游依据：`plan/03-架构与技术选型.md`
- 每个模块给：输入 / 输出 / 确定性纪律 / 验收判据 / 依赖。**"动了会打挂测试"的口径在文末 K 清单登记。**

## 模块 1：双源抓取（`fetch.py`）

**输入**：频道标识 `gwy` / `bm`；页数与每页条数；延时秒数。

**输出**：统一 schema 的 `PolicyItem` 列表 + 抓取元信息（每频道：请求 URL、HTTP 状态、`totalCount`、实际取到条数、抓取时间戳）。

**实测锚点（2026-10-17 复测，见 `data/README.md`）**：
- 条目在 `searchVO.listVO`（**顶层 `data` 字段实测为 `null`**，不得按 `data` 取）。
- 分页参数 `p` / `n` 生效：`p=2` 返回第 11–20 条（`p=1` 首条 id `26772701`，`p=2` 首条 id `26509115`）。
- `sort=pubtime&sortType=1` 倒序生效。
- 响应 `searchVO.totalCount` 是**真实总数**，而 `pageSize` 是请求回显。

**确定性纪律**：
1. **限频**：逐页抓取之间固定延时（默认 1.5s，可配），**不做高并发**。同一进程内两频道串行。
2. **超时 + 重试**：单请求超时 20s，失败重试 2 次（指数退避）；两次不同渠道都失败 → 该频道记 `degraded`，**不中断另一频道**（失败隔离）。
3. **抓取自证（skill"接口报的总数要对账"）**：断言 `len(实际取到) == min(请求条数, totalCount - 已取)`；不符即 exit 4 并打印实际/声明两数。**不得**用 `totalCount` 直接当"我拿到了这么多"。
4. **不拼 URL**：抓取目标只从 API 返回的 `url` 字段取值（决策 D2）；本模块对 `url` 字段只做非空校验，不发正文请求。
5. **无时钟参与判定**：抓取时间戳只进元信息（供留档），**不参与任何 diff/解析/命中判定**。

**验收判据**：
- 真实抓取一次（`fetch --channel gwy --pages 1 --n 5`），产出的条目 schema 与 `data/README.md` 留档样本逐字段一致（测试用**冻结的 API 响应样本**离线回归，不打真站点）。
- 总条数对账行真打印（`请求 N 条 / 声明 totalCount M / 实际 K`）。
- 网络不可达时 exit 4，不留半个产物（原子写）。

**依赖**：`model.py`（schema）、`serialize.py`（写盘）、`errors.py`。

## 模块 2：快照存储 + 新增检测（`snapshot.py`）

**输入**：本次抓取的 `PolicyItem` 列表 + 上次本地快照文件（可为空 = 首次运行）。

**输出**：① 更新后的快照文件；② 新增条目清单；③ diff 元信息（本次总数 / 上次总数 / 新增数 / 重复数 / 主键口径）。

**实测锚点**：部委频道 `index` 实测 30/30 为空 → **去重主键用 `id`**，`index` 只作副键。

**确定性纪律**：
1. **变更检测一律走上次快照 diff**（决策 D3，日期参数未生效）。
2. **重复判定双键**：`id` 相同 → 重复；或 `pcode` 相同且非空 → 重复。**两键任一命中即判重复**，命中的键写进 `matched_by` 供回溯。`pcode` 为空时只按 `id` 判。
3. **同输入同输出**：同一对快照（A, B）必须得到同一份新增清单。守门 = **双跑逐字节一致**（序列化后 JSON diff 为空），且**清单顺序按 `(pubtimeStr 倒序, id 升序)`** 固定，不依赖 dict 迭代序或 set 序。
4. **快照只存元数据**：字段白名单 = PolicyItem 全部字段；**不落全文**（边界 2）。快照里出现 `content`/`body`/`fulltext` 一类字段即红。
5. **append-only 不做**：快照是全量覆盖式更新（每次抓取结果即新快照），历史轮次由版本控制留档，不引入事件流（首期无重放需求）。

**验收判据**：
- 预置快照对（`data/snapshots/pair-A.json` / `pair-B.json`）跑 diff，新增清单与 `data/truth/diff-truth.json` 逐条一致（真值台账）。
- 真值台账**含两类样本**：应判新增 + 应判重复（题面评分"真值基准覆盖'应判新增/重复'两类样本"）。
- **边界样本**：`pcode` 为空的部委条目（只能按 `id` 判重复）必须有样本覆盖。

**依赖**：`model.py`、`serialize.py`。

## 模块 3：文号与部门解析（`parse.py`）

**输入**：条目的 `pcode` 与 `puborg`。

**输出**：文号解析结构 + 部门归一化结果 + **未解析显式标记**。

**实测文号形态（2026-10-17 实采，全部为真实返回值）**：

| 形态 | 实例 | 解析结构 |
|---|---|---|
| 标准六角括号 | `国办发〔2026〕28号` | 代字 `国办发` / 年份 `2026` / 序号 `28` |
| 无"号"字变体 | `国函〔2026〕105号` | 代字 `国函` / 年份 `2026` / 序号 `105` |
| **序号含汉字前缀** | `国令第847号` | 代字 `国令` / 年份 **未解析** / 序号 `847` |
| 多字代字 | `国知发服字〔2026〕29号` | 代字 `国知发服字` / 年份 `2026` / 序号 `29` |
| 多部门联发代字 | `工信部联规函〔2026〕239号` | 代字 `工信部联规函` / 年份 `2026` / 序号 `239` |
| **空 pcode** | `""` | 全字段 `未解析`（实测部委 3/30 为空） |

**确定性纪律**：
1. **规则化解析，不做语义猜测**。代字 = `〔` 之前的全部非空字符（实测代字可含 `字`、`联规` 等，不做白名单硬编码，否则 `国知发服字` 类被误判）；年份 = `〔YYYY〕` 内的四位数字；序号 = `〕` 之后到 `号` 之前的数字串。
2. **失败显式"未解析"**：`国令第847号` 无 `〔〕` → 年份字段标 `未解析`，**不编造年份**。整条 `pcode` 为空 → 三个字段全 `未解析`。
3. **解析结果三态**：`parsed`（全字段解析成功）/ `partial`（部分字段未解析）/ `unparsed`（整条未解析）。**不把 partial 当 parsed**。
4. **部门归一**：`puborg` 实测为**空格分隔多部门**（如 `国家发展改革委 民政部 国家卫生健康委`）→ 按空格拆分，逐部门查别名表归一；别名表**单一来源**（`data/config/org-aliases.json`），解析层不另建第二份。认不出的部门原样保留 + 标 `alias_missing`（**不猜**）。
5. **别名匹配最长优先**（防短串吃掉长串前缀，skill petfood 条）。

**验收判据**：
- `data/truth/pcode-truth.json` 逐条标注期望解析结构，基准逐条对账；**解析失败样本显式标注"未解析"**，基准核对"确实标了未解析"而非"解析出了什么"。
- 反向样例：`国令第847号`（不该解析出年份）、空 pcode（不该解析出代字）必须有样本。

**依赖**：`serialize.py`、`data/config/org-aliases.json`。

## 模块 4：关键词订阅 + 命中（`subscribe.py`）

**输入**：订阅配置（`include` 多关键词 + `exclude` 排除词）+ 模块 2 的新增条目。

**输出**：命中清单（`item_id` / `matched_keyword` / `matched_field`（title/summary）/ `hit_count`）。

**确定性纪律**：
1. **确定性匹配**：子串包含判定（`keyword in title or keyword in summary`），**不做相关性打分、不做分词、不做模糊匹配**。
2. **命中可回溯**：每条命中记录命中字段与命中位置（`title`/`summary` + 该词的起始下标），**不重算**。
3. **去重**：同一关键词多次配置（配置里重复出现）只产生一条命中（按关键词归一后去重）；同一条目命中多个词 → 产生多条命中记录（每词一条），但在日报里合并呈现。
4. **排除优先**：命中 `exclude` 词的条目**整条不进日报**（不是"不标注"），并在 diff 元信息里记 `excluded_count`。
5. **大小写与全半角**：中文无大小写问题；`include` 词做 **全角/半角归一**后再匹配（防 `〔`/`(` 类差异漏命中）——归一表单一来源。

**验收判据**：
- 订阅样例配置（含多词、含排除词、含重复词）跑匹配，命中清单与 `data/truth/subscribe-truth.json` 逐条一致。
- **边界样本**：命中恰好 0 次的条目、只命中 exclude 的条目、同词重复配置的条目。
- 阳性对照：把关键词换成必然命中的词 → 命中数必须 > 0（防"永远不命中"的假门）。

**依赖**：`model.py`、`serialize.py`。

## 模块 5：中文日报生成（`report.py`）

**输入**：新增条目 + 命中清单 + 解析结果 + diff 元信息。

**输出**：中文 Markdown 日报 + HTML 日报（同一渲染源，两格式内容一致）。

**确定性纪律**：
1. **单一渲染源**：`report_sections()` 返回结构化章节，Markdown 与 HTML 渲染器各自读它 → "两格式内容一致"是**结构性质**，不靠人工比对。
2. **排序**：按 `pubtimeStr` 倒序，同日期按 `id` 升序（与模块 2 一致）。
3. **每条必含**：标题 / 文号（原文 + 解析结构）/ 发布部门（原文 + 归一结果）/ 发布日期 / 摘要 / 原文链接 / 命中关键词标注。缺任一字段该条**不静默略过**，而是显式渲染 `未提供`。
4. **未挂原文核对不落库/不生效**（FR-11，代码级门禁）：日报渲染前断言"每条进日报的条目都通过了 schema 校验且字段来自 API 实测值"；校验失败即**该条不进日报**并计数 `dropped_count`，退出码 1（降级完成）——**不伪造字段**。
5. **渲染层零判定**：只消费既有结论，不重算 diff/解析/命中。
6. **零外链（本地可开）**：HTML 无 `<link>`、无外链 `script`/`img`、无 `@import`、无外部字体，CSS 全内联 → `assert_no_external_resources()` **常驻在渲染出口**（不是只在测试里验一次）。
7. **字节可复现**：同输入两次渲染逐字节一致（无时间戳、无随机序）。
8. **不做解读**（边界 1）：文案模板零判断语句。

**验收判据**：
- 日报可由 `data/snapshots/` + `data/truth/` + 订阅配置**完全复现**（题面要求），双跑逐字节一致。
- HTML 0 外链硬断言；Markdown/HTML 内容逐项对等断言（抽文本比对，不是断言"都调了同一个函数"）。
- 空数据三态：无新增 → 日报显式写"本次无新增"（不落空文件）；无输入源 → exit 3/4 且**不产报告**。

**依赖**：`model.py`、`serialize.py`、`data/config/`。

## 编排层：一条命令出结果（`pipeline.py`）

`run` = `fetch → snapshot diff → parse → subscribe → report`。CLI 与任何未来形态**共用同一编排函数**（上收为公开函数组），测试断言**行为等价**（CLI stdout 的统计 == 直调编排的统计 == 报告里的统计），不是"都调了同一个函数"这种字面声明。
