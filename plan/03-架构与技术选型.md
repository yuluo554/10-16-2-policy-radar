# 03：架构与技术选型

- 上游依据：`plan/02-需求解读与边界.md`
- 本文作用：定分层、定技术栈、定文件布局、定统一 schema。**改本文件的分层与 schema 属"动了会打挂测试"的口径变更**（登记进 HANDOFF 的 K 清单）。

## 一、技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | Python **≥3.8** | 题面"纯本地 Python CLI"；本机底线解释器 3.8.8（`py -0p` 实测），CI 矩阵含 3.8。**全部代码只能用 3.8 语法** |
| 运行时依赖 | **零第三方**（仅 stdlib） | 抓取用 `urllib.request`；JSON 用 `json`；解析用 `re`；CLI 用 `argparse`；日报写盘用 `io`。零依赖 = 干净环境秒装、断网可跑、无供应链面 |
| 测试期依赖 | `pytest`（dev extra） | 仅测试用；`[dev]` 是唯一 extras |
| 大模型 | **不使用**（决策 D6） | 文号是结构化字段，无解析兜底需求；结论 100% 可复现 |
| 打包 | 不做 exe；交付**源码包 + editable 安装** | 题面形态为 CLI；省掉打包面复杂度 |
| 确定性 RNG | 自研 splitmix64（生成器用） | 禁 stdlib `random`（不承诺跨版本序列一致）；快照对生成器必须跨机可复现 |
| 编码 | 源码 UTF-8；写盘 `open(..., newline="\n")` | 中文项目；`Path.write_text(newline=)` 是 3.10+ 参数，3.8 上用 `open` 或 `write_bytes`；`ensure_ascii=False` |

## 二、分层

```
┌─────────────────────────────────────────────┐
│  CLI 层  policy_radar/cli.py                │  argparse 子命令、退出码、编码守卫
│           policy_radar/__main__.py          │  使 `python -m policy_radar` 可执行
├─────────────────────────────────────────────┤
│  编排层  policy_radar/pipeline.py           │  run 一条龙：fetch→diff→parse→digest
├──────────────┬──────────────┬───────────────┤
│ fetch.py     │ snapshot.py  │ parse.py      │  subscribe.py   report.py
│ 双源抓取      │ 快照/diff     │ 文号+部门      │ 订阅匹配        日报渲染
├──────────────┴──────────────┴───────────────┤
│  模型层  policy_radar/model.py              │  统一中间表示 PolicyItem
│          policy_radar/serialize.py          │  唯一写盘单点（冻结 JSON 序列化参数）
├─────────────────────────────────────────────┤
│  数据层  data/                              │  预置快照对、真值台账、订阅样例、规则表
└─────────────────────────────────────────────┘
```

**分层纪律（skill 同款）**：

- **写盘单点**：所有产物（快照、新增清单、日报、真值）一律经 `serialize.write_json()` / `write_text()`，不在各模块各写各的 `open()+json.dump()`。序列化参数冻结为契约（见 K 清单）：`json.dumps(sort_keys=True, ensure_ascii=False, indent=2)` + LF + 结尾换行 + 原子写（临时文件 → rename）。
- **渲染层零判定**：`report.py` 只消费 `diff`/`parse`/`subscribe` 的既有结论，**不得重算任何判定**。
- **判定口径单一实现源**：新增/重复判定只在 `snapshot.py` 一处；文号解析只在 `parse.py` 一处；订阅命中只在 `subscribe.py` 一处。测试与基准**import 生产实现**，不得各写一份（防"预览 loader 与生产 loader 分叉"）。

## 三、统一中间表示（PolicyItem）

两个频道返回字段一致（`data/README.md` 二节实测），统一为：

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `source` | str | 我方可加 | 频道标识：`gwy` / `bm`（API 未返回，抓取时注入） |
| `id` | str | API `id` | **主键**。实测两频道均非空（gwy/30 与 bm/30 全有） |
| `index` | str | API `index` | 去重副键。**实测部委频道 30/30 为空**，故只能作副键，不可作唯一主键 |
| `pcode` | str | API `pcode` | 文号原文。**实测部委频道 3/30 为空**，可空 |
| `title` | str | API `title` | 标题，实测非空 |
| `pubtimeStr` | str | API `pubtimeStr` | 发布日期 `YYYY.MM.DD`，实测非空 |
| `puborg` | str | API `puborg` | 发布机关原文。**实测部委为空格分隔多部门**（如 `国家发展改革委 民政部 国家卫生健康委`） |
| `url` | str | API `url` | 原文链接，实测非空 |
| `summary` | str | API `summary` | 摘要，实测非空（含标题与文号重复片段） |
| `channel` | str | 我方可加 | 中文频道名，渲染用 |

**显式排除**：`fwzh` / `wenhao` / `wjlx` 三个字段**实测 60/60 全空**（两频道各 30 条）→ 不作为任何判定依据，仅原样保留在 raw 中备查。`piclinksurl`/`imgurl`/`theme`/`personal` 等 UI 字段不入模型。

## 四、CLI 子命令与退出码（M0 定稿，锁进测试）

| 子命令 | 里程碑 | M0 行为 |
|---|---|---|
| `fetch` | M2 | exit 3（能力未就绪） |
| `diff` | M3 | exit 3 |
| `parse` | M3 | exit 3 |
| `digest` | M5 | exit 3 |
| `run` | M5 | exit 3 |
| `bench` | M4 | exit 3 |
| `selftest` | M0 | **已实现且可证伪**（见下） |
| `version` | M0 | 打印版本 exit 0 |

| 退出码 | 语义 | 触发 |
|---|---|---|
| 0 | 成功完成 | 命令正常跑完且结论无异常 |
| 1 | 完成但有降级/检出问题 | 如部分频道抓取失败（降级完成）；基准未达标 |
| 2 | 用法错误 / 输入不可用 | 未知子命令、参数错、输入文件缺失、坏格式 |
| 3 | **能力未就绪（骨架期专用，模块落地后整项退役）** | 未实现模块被调用时**不伪造空结果**，显式拒绝 |
| 4 | 外部依赖不可用 | 网络不可达、API 返回非 200、API 结构异常 |

**退出码 3 的退役流程（skill K2，四处同步，少一处即幽灵语义复活）**：模块落地 → 删常量 → 改 CLI/退出码/selftest 测试（含 `not hasattr` 防复活）→ 改 README 退出码表 → 改决策记录。

**`selftest` 可证伪（防"恒 True 空壳"）**：真跑以下断言，任一不成立即 exit 1：
① 包可导入且 `__version__` 与 pyproject 一致；② 退出码常量齐备（0/1/2/3/4）；③ 统一 schema 字段常量齐备；④ 数据根存在且含预期子目录；⑤ 序列化单点可写。
**阴性对照**：把数据根指向空目录 → 必须返回非 0（测试锁死）。

**M0 实际落盘的文件**：`__init__.py` / `__main__.py` / `cli.py` / `errors.py` / `model.py` /
`serialize.py` / `paths.py` + 上述 `tests/` 五个测试文件 + CI + README + `data/` 四个空子目录
（各带 README 说明它是哪个里程碑的产出）。

**不落"空壳桩"**：`fetch.py` 等模块在 M0 **不创建**——skill 实测教训是"空 `pass` 测试 /
`NotImplementedError` 桩函数 / `placeholder` manifest 会静默混过里程碑、而 DoD 却逐项打 ✅"。
M0 的未就绪能力由 CLI 的 **exit 3** 显式表达（不伪造空结果），模块落地时**新建真文件**
而非"填掉一个桩"。收尾期固定扫一遍 `grep -rn "NotImplementedError\|TODO: 实现\|placeholder" src/ tools/ tests/` 作为哨兵串排查。

**安装面纪律（skill 四/五面）**：`package-dir = {"" = "src"}` + `packages.find where=["src"]`；`policy_radar` 必须在 include 里；运行时读的数据文件（`data/`）以**包外相对路径**定位 → README「已知环境问题」节写明"首期发布物是源码包 + editable 安装"，并声明 wheel 安装不受支持（**不写成"已验证 wheel"**）。
